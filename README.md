# GitHelper

GitHelper는 Windows에서 로컬 커밋을 작업 브랜치와 PR로 옮겨 기본 브랜치에 반영하는 Git 작업 도우미입니다.

로컬 기본 브랜치에서 작업한 뒤 필요한 내용만 커밋하면 GitHelper가 다음 과정을 처리합니다.

1. 최신 원격 기본 브랜치에서 임시 feature 브랜치를 생성합니다.
2. 처리할 로컬 커밋을 feature 브랜치에 순서대로 적용합니다.
3. feature 브랜치를 Push하고 PR을 생성합니다.
4. PR을 Rebase merge합니다.
5. 로컬 기본 브랜치를 최신 상태로 맞춥니다.
6. 설정에 따라 로컬·원격 feature 브랜치를 정리합니다.

`main`에서 직접 Push하거나 `main`을 작업 브랜치로 병합하는 동작은 차단됩니다.

## 화면 구성

![GitHelper 메인 화면](docs/images/main-window.png)

- **Repository**: 작업할 Git 저장소 경로입니다.
- **기본 브랜치**: 커밋 비교, feature 분기, PR 대상 및 병합 후 동기화 기준입니다. 기본값은 `develop`이며 저장소별로 기억됩니다.
- **처리할 커밋**: `origin/<기본 브랜치>` 이후 현재 HEAD까지 존재하는 로컬 커밋입니다.
- **내 Push 목록**: 현재 저장소의 `origin`에 반영된 커밋 중 현재 `git user.email` 작성자의 커밋입니다.
- **Feature branch 이름**: PR에 사용할 임시 작업 브랜치 이름입니다. 최근 커밋 메시지를 바탕으로 자동 제안됩니다.
- **머지 후 feature 브랜치**: 병합 후 임시 브랜치를 삭제할지 유지할지 선택합니다.
- **진행 로그**: Push, PR, 병합, stash 복원 및 브랜치 삭제 결과를 표시합니다.

창을 키우면 처리할 커밋, 내 Push 목록, 진행 로그 영역이 함께 늘어납니다.

## 준비 사항

- Windows
- Git
- 원격 저장소의 Push 및 PR 생성 권한
- GitHub CLI(`gh`)

Git이 없으면 프로그램 시작 시 `winget`으로 Git for Windows를 자동 설치합니다. Git이 설치되어 있지만 PATH에 없으면 일반 설치 위치를 찾아 사용자 PATH에 자동 등록합니다.

GitHub CLI가 없으면 필요한 시점에 `winget` 설치를 안내합니다. GitHub 로그인이 필요하면 브라우저 인증 화면을 열고 인증 완료 후 계속합니다.

GitHub CLI에 여러 계정이 로그인되어 있으면 현재 `origin` 저장소에 push 권한이 있는 계정을 자동으로 확인합니다. 사용할 수 있는 계정이 하나면 자동 전환하고, 여러 개면 작업 전에 선택창을 표시합니다.

내 Push 목록을 구분하려면 Git 사용자 이메일도 설정되어 있어야 합니다.

```powershell
git config user.email
```

## 빠른 사용법

### 1. 저장소 선택

`변경...`을 눌러 Git 저장소 폴더를 선택합니다. 경로를 직접 입력한 경우 `Enter`를 누르거나 다른 컨트롤로 이동하면 저장소를 다시 읽습니다.

자주 사용하는 저장소는 `+ 즐겨찾기`로 등록할 수 있습니다. Repository 목록에서 등록된 저장소로 바로 전환할 수 있으며, `− 제거`는 현재 경로를 즐겨찾기에서만 제거합니다.

### 2. 기본 브랜치 확인

화면 위쪽의 **기본 브랜치** 목록에서 기준 브랜치를 선택합니다.

- 기본값: `develop`
- 선택 항목: 현재 저장소의 `origin`에 존재하는 원격 브랜치
- 저장 방식: 저장소별로 마지막 선택값 저장

기본 브랜치를 바꾸면 처리할 커밋, 변경 파일, feature 브랜치 시작 지점, PR base 및 병합 후 동기화 대상이 모두 새 기준으로 다시 계산됩니다.

### 3. 로컬 변경 커밋

원하는 파일만 직접 커밋합니다. GitHelper는 커밋을 생성하지 않으며 이미 존재하는 커밋만 처리합니다.

```powershell
git add <파일>
git commit -m "feat(scope): 변경 내용"
```

커밋 후 `새로고침`을 누릅니다. **처리할 커밋** 영역에 반영하려는 커밋이 모두 표시되는지 확인합니다.

> 처리할 커밋에 표시된 커밋은 전부 feature 브랜치에 적용됩니다. 관련 없는 커밋이 섞여 있다면 실행하기 전에 커밋 구성을 먼저 정리해야 합니다.

### 4. 변경 파일 확인

`변경 파일 보기`를 누르면 처리 대상 커밋에 포함된 파일을 확인할 수 있습니다.

- Prefab: `.prefab`
- C#: `.cs`
- 이미지: `.png`, `.jpg`, `.tga`, `.psd`, `.svg` 등
- Material: `.mat`
- Shader: `.shader`, `.shadergraph`, `.shadersubgraph`, `.vfx`, `.compute`

파일이 없는 분류는 표시되지 않습니다. 목록에는 경로와 확장자를 제외한 파일명만 표시됩니다.

변경 파일 창 사용법:

- 분류 제목 더블 클릭: 해당 분류 접기 또는 펼치기
- `전체 펼치기` / `전체 접기`: 모든 분류 상태 변경
- `Ctrl+A`: 현재 펼쳐진 파일 전체 선택
- `Ctrl+C`: 선택한 파일명 복사
- `선택 항목 복사`: 선택한 파일명을 줄바꿈 형식으로 복사

### 5. 기본 브랜치에 반영

자동 제안된 feature 브랜치 이름을 확인하고 필요하면 수정합니다. 브랜치 이름에는 영문, 숫자, `.`, `_`, `/`, `-`를 사용할 수 있습니다.

머지 후 브랜치 처리 방식을 선택한 뒤 `Develop에 반영`을 누릅니다. 버튼 이름은 기존 명칭이지만 실제 PR 대상은 화면 위에서 선택한 **기본 브랜치**입니다.

실행 중에는 다음 과정이 자동으로 진행됩니다.

1. 원격 저장소 fetch
2. 미커밋 파일이 있으면 stash로 임시 보호
3. `origin/<기본 브랜치>`에서 feature 브랜치 생성
4. 처리할 커밋을 순서대로 cherry-pick
5. feature 브랜치 Push
6. 기본 브랜치 대상 PR 생성
7. Rebase merge
8. 최신 원격 기본 브랜치 fetch 및 로컬 동기화
9. stash 복원
10. 선택에 따라 로컬·원격 feature 브랜치 삭제

리뷰나 CI가 필수인 저장소에서는 GitHub 보호 규칙에 의해 즉시 병합이 거부될 수 있습니다. 이 경우 표시된 PR에서 조건을 먼저 충족해야 합니다.

## 내 Push 목록 사용법

내 Push 목록은 별도 기록 파일이 아니라 현재 저장소의 Git 원격 추적 기록을 직접 읽습니다. 저장소를 전환하면 해당 저장소의 목록으로 다시 바뀝니다.

조회 기준:

- `origin` 원격 브랜치에 실제로 포함된 커밋
- 현재 저장소의 `git config user.email`과 작성자 이메일이 일치하는 커밋
- 최신 커밋부터 최대 200개

Push 커밋 하나 또는 여러 개를 선택한 뒤 `변경 파일 보기`를 누르면 선택한 커밋들의 변경 파일을 합쳐서 표시합니다. 처리할 커밋 목록을 다시 선택하면 변경 파일 보기는 현재 처리 대상 기준으로 동작합니다.

Rebase merge로 SHA가 달라진 커밋도 원격 기본 브랜치에 작성자 정보가 유지되어 있으면 목록에 표시됩니다.

## 기타 기능

### 최근 커밋 되돌리기

처리할 커밋 중 가장 최근 커밋을 `mixed reset`으로 취소합니다. 커밋 기록만 취소하고 변경 내용은 작업 폴더에 그대로 남깁니다. 원격 저장소에는 영향을 주지 않습니다.

### 현재 커밋에서 브랜치 생성

현재 HEAD에서 새 로컬 브랜치를 만들고 바로 이동합니다. 미커밋 파일은 그대로 유지됩니다. 이 기능은 브랜치를 원격에 자동 Push하지 않습니다.

### 현재 브랜치를 기본 브랜치에 병합

현재 브랜치를 먼저 Push한 뒤 선택한 기본 브랜치 대상 PR을 만들고 Rebase merge합니다.

- 현재 브랜치가 기본 브랜치이면 사용할 수 없습니다.
- 현재 브랜치가 `main`이면 사용할 수 없습니다.
- 병합 후 선택에 따라 로컬·원격 작업 브랜치를 삭제합니다.

### 업데이트 확인

GitHub Release에서 새 버전을 확인합니다. 새 버전이 있으면 변경 내역을 보여주고 동의 시 실행 파일을 교체합니다. 프로그램 시작 시에도 자동으로 확인합니다.

## 문제 해결

### 처리할 커밋이 0개인 경우

- 변경 내용을 실제로 커밋했는지 확인합니다.
- 선택한 기본 브랜치가 맞는지 확인합니다.
- 현재 커밋이 이미 `origin/<기본 브랜치>`에 반영되었는지 확인합니다.
- `새로고침`을 눌러 다시 조회합니다.

### 기본 브랜치를 찾을 수 없는 경우

상단 기본 브랜치 목록에서 실제 `origin`에 존재하는 브랜치를 선택합니다. 필요한 브랜치가 보이지 않으면 원격 설정과 fetch 권한을 확인합니다.

### 내 Push 목록이 비어 있는 경우

현재 저장소의 이메일 설정을 확인합니다.

```powershell
git config user.email
git log --remotes=origin --author="내 이메일"
```

다른 이메일로 작성된 커밋은 목록에 표시되지 않습니다.

### 원격 브랜치가 삭제되지 않는 경우

GitHelper는 삭제 요청 후 `git ls-remote`로 원격 브랜치가 실제로 사라졌는지 다시 확인합니다. 브랜치 보호나 권한 문제로 남아 있으면 작업을 성공으로 표시하지 않고 Git 오류를 진행 로그에 남깁니다.

### 인증에 실패하는 경우

```powershell
gh auth status --hostname github.com
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
```

저장소의 `origin` 주소와 계정의 Push 권한도 함께 확인합니다.

## 실행

GitHub Releases에서 최신 `GitHelper.exe`를 내려받아 실행합니다. 별도 설치 과정은 없습니다.

## 빌드

PowerShell에서 `ps2exe` 모듈을 설치한 다음 빌드합니다.

```powershell
Install-Module ps2exe -Scope CurrentUser
.\Source\Build-Release.ps1 -Version 1.0.4
```

결과물은 `EXE/GitHelper.exe`와 `EXE/GitHelper.zip`에 생성됩니다. 버전별 변경사항은 [CHANGELOG.md](CHANGELOG.md)를 참고하세요.
